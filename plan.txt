7.13
2. 异常 dt 为什么危险
{
    正常情况下，调度器每 5 ms 读取一次编码器：
speed = 编码器脉冲数 / 4635.6 / dt * 10
相关代码在 [scheduler.cpp (line 36)](/home/loren/桌面/LS2K0300_Library/LS2K300_Library/Seekfree_LS2K0300_Opensource_Library/project/code/scheduler.cpp:36) 和 [encoder.cpp (line 37)](/home/loren/桌面/LS2K0300_Library/LS2K300_Library/Seekfree_LS2K0300_Opensource_Library/project/code/Control/Control_Source/encoder.cpp:37)。
举个例子，假设正常 5 ms 内产生 100 个脉冲：
速度 = 100 / 4635.6 / 0.005 * 10 ≈ 43.1
如果控制线程因系统调度、驱动调用等原因卡住 500 ms，那么编码器可能累计约 10000 个脉冲。此时代码检测到 dt > 0.2，却把 dt 改成 0.005：
错误速度 = 10000 / 4635.6 / 0.005 * 10 ≈ 4314
真实速度 = 10000 / 4635.6 / 0.5 * 10 ≈ 43.1
虽然当前编码器计数先经过 0.25 系数的滤波，但第一次恢复时仍大约会得到：
滤波计数 = 0.75 × 100 + 0.25 × 10000 = 2575
反馈速度 ≈ 1111
假设目标速度为 95，PID 看到的误差会突然变成约 95 - 1111 = -1016。速度 PID 很容易立即达到负向限幅，最终在 [scheduler.cpp (line 125)](/home/loren/桌面/LS2K0300_Library/LS2K300_Library/Seekfree_LS2K0300_Opensource_Library/project/code/scheduler.cpp:125) 输出接近 -50，即电机突然强力反转或制动。之后滤波值还需要几个周期才能衰减，车辆可能连续抖动。
更长的停顿还可能让脉冲数超过 int16_t 的 32767，在 [encoder.cpp (line 40)](/home/loren/桌面/LS2K0300_Library/LS2K300_Library/Seekfree_LS2K0300_Opensource_Library/project/code/Control/Control_Source/encoder.cpp:40) 转换时发生符号翻转。
推荐这样优化：
使用 steady_clock 计算时间，保证单调递增。
不要把异常的真实 dt 伪造成 5 ms。
发生严重超时时直接停车、丢弃累计脉冲、清 PID，并跳过本轮控制。
正常周期中先用真实 dt 算“原始速度”，再对速度进行滤波，而不是先滤波脉冲再除以变化的 dt。
核心处理可以设计为：
if (dt > k_control_timeout)
{
    motor_stop();
    pwm_l = pwm_r = 0.0f;

    encoder_reset();       // 清硬件计数、速度值和滤波状态
    pid_left.clear();
    pid_right.clear();
    pid_angle.clear();

    dt_sum_10ms = 0.0f;
    return;                // 本周期不运行 PID
}
建议设置两个阈值：例如超过 20～30 ms 记录调度异常，超过 100～200 ms执行停车保护。具体阈值需要根据实车 Linux 调度抖动测试确定。
}

如果摄像头的高度、俯仰角、左右位置或朝向发生变化，最重要的是重新标定 IPM。PID 参数不是第一优先级，应该先保证图像坐标正确。
必须修改：IPM 矩阵
当前原图到 IPM 的 3×3 矩阵在 [image_test.cpp (line 767)](/home/loren/桌面/LS2K0300_Library/LS2K300_Library/Seekfree_LS2K0300_Opensource_Library/project/code/image_test.cpp:767)：

    {0.071098..., 13.161169..., -252.156...},
    {0.001562..., 0.084822..., 1},
};
下列任何变化都会使旧矩阵失效：
摄像头安装高度改变
俯仰角改变
摄像头左右移动
摄像头没有正对车头，发生偏航
更换镜头或视场角
修改输入分辨率、裁剪范围或缩放方式
当前矩阵使用的是原始 320×240 图像缩放后的 160×120 坐标，缩放代码在 [image_test.cpp (line 5130)](/home/loren/桌面/LS2K0300_Library/LS2K300_Library/Seekfree_LS2K0300_Opensource_Library/project/code/image_test.cpp:5130)。重新标定时，采点也必须使用缩放后的 160×120 坐标，不能直接把 320×240 坐标填进矩阵。
标定完成后应检查：
直道左右边线在 IPM 中基本平行
车辆正前方的赛道中线接近 x = 79
同一条赛道从近处到远处宽度变化不大
左右边线没有整体倾斜或横向漂移
需要验证：车身参考点
Pure Pursuit 当前认为车辆位于 IPM 坐标：

constexpr float k_vehicle_y = 138.0f;
位置在 [car_control.cpp (line 28)](/home/loren/桌面/LS2K0300_Library/LS2K300_Library/Seekfree_LS2K0300_Opensource_Library/project/code/car_control.cpp:28)。
其中：

如果重新生成的 IPM 仍保持相同坐标尺度，并让车辆中心仍对应 x≈79，这两个参数可以不改。否则必须重新确定，特别是摄像头左右移动后，k_vehicle_x 很容易不再是 79。
需要验证：IPM 路宽和中线偏移
正常巡线使用可靠边向内偏移半个路宽：

重新标定后，在直道上测量：
IPM 路宽 = 右边线 x - 左边线 x
中线偏移 = IPM 路宽 / 2
例如新 IPM 路宽约为 50 px，就应改为：

如果重新标定时保持原来的 IPM 尺度和约 45 px 路宽，则仍可使用 22.5。
